## Quick Viva Cheat-Sheet for Students

When an examiner asks:
1. *"Where is runtime polymorphism demonstrated?"*
   - Answer: Look at [`AllocationPolicy`](file:///Users/hardik/Desktop/OOPS_IA/include/smartcampus/policies/AllocationPolicy.hpp). The base class declares `virtual map<string, EnergyAllocation> allocate(...) = 0;`. Both [`PriorityPolicy`](file:///Users/hardik/Desktop/OOPS_IA/src/policies/PriorityPolicy.cpp) and [`FairSharePolicy`](file:///Users/hardik/Desktop/OOPS_IA/src/policies/FairSharePolicy.cpp) override it. [`AllocationEngine`](file:///Users/hardik/Desktop/OOPS_IA/src/engine/AllocationEngine.cpp) calls `m_currentPolicy->allocate()` through a base pointer, dispatching to the selected algorithm dynamically at runtime.
2. *"Where is multilevel inheritance demonstrated?"*
   - Answer: In the building hierarchy: [`Building`](file:///Users/hardik/Desktop/OOPS_IA/include/smartcampus/models/Building.hpp) (base) $\to$ [`AcademicBuilding`](file:///Users/hardik/Desktop/OOPS_IA/include/smartcampus/models/AcademicBuilding.hpp) (derived level 1) $\to$ [`Laboratory`](file:///Users/hardik/Desktop/OOPS_IA/include/smartcampus/models/Laboratory.hpp) (derived level 2).
3. *"Why did you use `std::unique_ptr` in `Campus` instead of raw pointers?"*
   - Answer: To adhere to Modern C++ RAII guidelines. `std::unique_ptr` guarantees exception-safe, deterministic cleanup of dynamically allocated polymorphic objects with zero risk of memory leaks and without needing manual `delete` in the destructor.
